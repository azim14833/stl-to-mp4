STL vs 3MF vs OBJ vs PLY: Which 3D File Format Should You Use?

If you design, sell or print 3D models you will keep meeting four file formats: STL, 3MF, OBJ and PLY. Most slicers open all of them, so they look interchangeable. They are not. Each one stores a different set of information, and the wrong choice shows up later as lost colours, a model that imports at the wrong size, or a download that is ten times larger than it needs to be. This guide explains what is actually inside each format so you can choose on purpose instead of by habit.

STL: the universal baseline

STL describes a surface as a list of triangles, and nothing else. Every triangle is stored with its own three corner points, so shared corners are written again and again. There is no colour, no material and no unit. A cube that is 40 units wide may be 40 mm or 40 inches; slicers simply assume millimetres.

STL comes in two encodings. ASCII STL is human-readable text and is several times larger than the binary version. Binary STL uses an 80-byte header, a 4-byte triangle count and then exactly 50 bytes per triangle. That gives you a handy rule of thumb: file size in bytes is about 84 + 50 × the number of triangles. A model with 200,000 triangles is therefore about 10 MB in binary STL, and one million triangles is about 50 MB. If you see a very large STL, check whether it was saved as ASCII before you blame the model.

Choose STL when compatibility matters more than anything else and the object is a single-colour solid. Almost every slicer, CAD tool, marketplace and viewer reads it.

3MF: the modern replacement

3MF is a zipped package of XML files. Inside you will find the mesh, the unit it was designed in, colours and materials, multiple objects, their positions on the build plate and, in many slicer-exported project files, print settings. Because the unit is stored in the file, a 3MF does not suffer from the scale confusion that plagues STL. Vertices are also shared between triangles instead of repeated, and the package is compressed, so a 3MF is usually much smaller than the equivalent STL.

The trade-offs are small but real. Not every older tool opens 3MF, and some slicers write their own vendor-specific settings into the file, which other programs ignore. If you sell models, offer 3MF next to STL: buyers with modern slicers get the better file, everyone else still has the baseline.

OBJ: meshes with materials

OBJ is an older text format used widely in modelling, sculpting and game tools. It can store polygons with more than three sides, surface normals and texture coordinates (UV maps). Colour and texture information lives in a separate .mtl file that points to image files. That is the main weakness for 3D printing: if the .mtl file or the texture images get separated from the .obj, the model arrives grey and untextured. OBJ also carries no unit, and because it is text, large meshes become heavy.

Pick OBJ when you need textures, or when you are handing a model between sculpting, rendering and animation software. When you share an OBJ, zip the .obj, .mtl and every texture file together.

PLY: scans and vertex colour

PLY (the Stanford polygon format) was designed for 3D scanning research. It stores a list of vertices and faces and lets you attach extra properties to each vertex, most commonly red, green and blue colour. That makes it the natural output for photogrammetry and full-colour scanners. It comes in ASCII and binary variants and handles dense meshes well. Support in print-focused tools is less consistent than for STL or 3MF, and PLY has no unit either.

What about other formats?

You will occasionally meet STEP and IGES (exact CAD geometry rather than triangles), AMF (an older attempt at a better STL, now largely replaced by 3MF) and glTF (a compact web and game format). STEP is worth keeping as your master file if you design in CAD, because you can always export a fresh STL at any resolution from it. A triangle mesh can never be turned back into exact CAD geometry without loss.

A simple decision guide

  • Single-colour print, maximum compatibility: binary STL.
  • Multi-part or multi-colour print, correct size guaranteed: 3MF.
  • Textured model or hand-off between art tools: OBJ with its .mtl and texture files.
  • Scanned or vertex-coloured model: PLY.
  • Editable design for yourself: keep the original CAD or project file as well.

Common mistakes

  • Exporting ASCII STL by accident and uploading a 60 MB file that should be 12 MB.
  • Sending an OBJ without its .mtl and textures.
  • Assuming the buyer knows the unit of an STL. State the real size in the listing.
  • Converting back and forth between formats. Every conversion is a chance to lose colours or change scale; export once from the original.

Check the file before you publish it

Whatever format you choose, open the exported file in a viewer before you upload it. Confirm three things: the model sits flat on the build plate, its dimensions match what you advertise, and the colours or parts you expect are present. A quick turntable preview reveals flipped faces, missing parts and odd orientation immediately, which is far cheaper than finding them through a buyer's complaint.

Frequently asked questions

Is 3MF always better than STL?

It is better in what it stores, but "better" depends on who opens the file. If your audience uses older software, a binary STL will open everywhere. Offering both is the safest choice.

Why is my STL so much bigger than the 3MF of the same model?

STL repeats every shared corner for each triangle and has no compression. 3MF shares vertices and is zipped, so the same geometry usually takes far less space.

Does converting STL to 3MF add colour?

No. Conversion only repackages the same triangles. Colour has to be added in a tool that supports it, such as a slicer or a modelling program.

Which format should I use for a figure with a painted texture?

Use OBJ or 3MF with textures when the colour is part of the product, for example full-colour printing services. For ordinary filament printing, texture is ignored, so a clean STL is enough.
